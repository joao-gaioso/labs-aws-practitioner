AWS Labs · Lab 03

EC2 Simples

AMI dinâmica · Security Group · Par de chaves · IMDSv2 · Free Tier

💻 EC2 🏗️ Terraform 🔑 SSH Key Pair 🛡️ IMDSv2 🔒 Security Group ☁️ Amazon Linux 2023

🎯 Objetivo

Criar uma instância EC2 com Terraform aplicando boas práticas: AMI dinâmica via data source, Security Group com regras explícitas, par de chaves gerado automaticamente e IMDSv2 habilitado.

📁 Estrutura dos arquivos

📁lab-03-ec2-simples/
📄versions.tf → versões fixadas (inclui providers tls e local)
📄provider.tf → provider AWS
📄variables.tf → variáveis de entrada
📄main.tf → EC2, Security Group, par de chaves, data sources
📄outputs.tf → IP público, comando SSH pronto
⚠️ Não esqueça de preencher o backend.tf!

Antes de rodar o terraform init, abra o arquivo backend.tf e substitua SEU-BUCKET-AQUI pelo nome real do seu bucket S3:

hcl · backend.tf 
terraform {
  backend "s3" {
    bucket  = "nome-do-seu-bucket-aqui"  # ← altere aqui
    key     = "lab-03-ec2-simples/terraform.tfstate"
    region  = "us-east-1"
  }
}
1. Edite o backend.tf com o nome real do bucket
2. Rode terraform init — ele vai configurar o backend automaticamente
3. Confirme com yes quando perguntado sobre migração do state

🔑
Par de chaves SSH

🛡️
Security Group
Regras explícitas de ingress (SSH) e egress — sem atalhos implícitos

🚀 Executando o lab

$ terraform init
$ terraform plan
$ terraform apply

Após o apply, o output comando_ssh já mostra o comando pronto para conectar:

bash
terraform output comando_ssh
# ssh -i lab-ec2-key.pem ec2-user@<IP_PUBLICO>

🔍 Verificando a instância

bash
# Ver o IP público
terraform output ip_publico

# Ver qual AMI foi usada
terraform output ami_utilizada

# Conectar via SSH
ssh -i lab-ec2-key.pem ec2-user@$(terraform output -raw ip_publico)

💡 Conceitos deste lab

data "aws_ami"

Busca a AMI mais recente do Amazon Linux 2023 sem hardcodar o ID. O ID muda por região e versão — data source resolve isso automaticamente.

data "aws_vpc"

Busca a VPC padrão da conta. Data sources leem recursos existentes sem criar nada novo.

Security Group

Firewall da EC2. Sempre declare ingress e egress explicitamente. Em produção, restrinja o SSH ao seu IP (SEU_IP/32).

tls_private_key

Gera um par de chaves RSA dentro do Terraform. Prático para labs; em produção gere fora e importe só a pública.

local_sensitive_file

Salva a chave privada localmente com permissão 0400. O sensitive garante que o conteúdo não apareça nos logs do Terraform.

metadata_options

http_tokens = "required" força IMDSv2, exigindo token de sessão para acessar metadados. Protege contra ataques SSRF.

user_data

Script executado na primeira inicialização da instância. Útil para instalar pacotes, configurar serviços, etc.

⚠️ Boas práticas de segurança aplicadas

🛡️
IMDSv2 obrigatório http_tokens = "required" — protege contra SSRF que tente acessar os metadados da instância
🔑
Chave privada com permissão restrita Salva como 0400 via local_sensitive_file — apenas o dono pode ler
🔒
Security Group com regras explícitas Ingress e egress declarados explicitamente — sem allow all implícito
🔄
AMI buscada dinamicamente Sem ID hardcoded — sempre usa a versão mais recente e correta para a região

🧹 Destruindo os recursos

bash
terraform destroy
⚠️

O arquivo .pem gerado localmente não é removido pelo destroy. Delete manualmente se necessário.
