AWS Labs · Lab 05

Route 53: DNS Privado

Hosted Zone privada · Registros A · Resolução de nomes dentro da VPC

🌐 Route 53 💻 EC2 + nginx 🏗️ Terraform 🔒 Hosted Zone Privada ☁️ us-east-1 🔑 SSH

🎯 Objetivo

Entender como o Route 53 funciona criando uma Hosted Zone privada e registros DNS que apontam para uma EC2. Você vai ver na prática como um nome como app.lojafacil.internal resolve para um IP — e o que acontece quando você muda as configurações.

A LojaFácil tem vários servidores internos na AWS. Em vez de os desenvolvedores decorarem IPs como 172.31.45.12, eles usam nomes como app.lojafacil.internal. Quando um servidor é substituído e o IP muda, basta atualizar o DNS — os desenvolvedores continuam usando o mesmo nome.

🏗️ Arquitetura

👤 Você (via SSH)
▼
💻 EC2 (nginx)
IP privado: 172.31.x.x
▲
📌 Route 53 Record A
app.lojafacil.internal → 172.31.x.x
▲
⬡ Hosted Zone Privada
lojafacil.internal
▲
🌐 VPC Padrão da conta
💡 A Hosted Zone é privada — o nome app.lojafacil.internal só resolve dentro da VPC. De fora da AWS, esse nome não existe.

📁 Estrutura dos arquivos

📁lab-05-route53-dns-privado/
📄versions.tf → versões fixadas
📄provider.tf → provider AWS
📄variables.tf → variáveis (incluindo dns_ttl para experimentos)
📄main.tf → EC2, Security Group, Hosted Zone, registros DNS
📄outputs.tf → IPs, nome DNS, comando SSH e de teste
⚠️ Não esqueça de preencher o backend.tf!

Antes de rodar o terraform init, abra o arquivo backend.tf e substitua SEU-BUCKET-AQUI pelo nome real do seu bucket S3:

hcl · backend.tf 
terraform {
  backend "s3" {
    bucket  = "nome-do-seu-bucket-aqui"  # ← altere aqui
    key     = "lab-05-route53-dns-privado/terraform.tfstate"
    region  = "us-east-1"
  }
}
1. Edite o backend.tf com o nome real do bucket
2. Rode terraform init — ele vai migrar o state automaticamente
3. Confirme com yes quando perguntado sobre migração do state

🚀 Deploy inicial

$ terraform init
$ terraform plan
$ terraform apply

Após o apply, anote os outputs — você vai precisar deles nos testes:

bash 
# Comando para conectar na EC2
terraform output comando_ssh

# Nome DNS criado
terraform output dominio_app

# IP para comparar com o DNS
terraform output ip_privado_ec2

✅ Verificação básica

Antes de começar os experimentos, confirme que tudo está funcionando.

1

Conecte na EC2 via SSH

O comando completo já aparece no output do Terraform:

bash 
ssh -i lojafacil-key.pem ec2-user@<IP_PUBLICO>
2

Dentro da EC2, teste a resolução DNS

bash · dentro da EC2 
# Deve retornar a página do nginx com "Bem-vinda ao lab Route 53!"
curl http://app.lojafacil.internal

# Deve mostrar o IP privado da EC2
dig app.lojafacil.internal +short
3

Compare o IP retornado pelo DNS com o IP da EC2

bash · dentro da EC2 
# IP privado da instância
hostname -I
✅

Os dois IPs devem ser iguais. Se sim, o DNS está funcionando corretamente!

⚠️

Lembre-se: dig e curl http://app.lojafacil.internal só funcionam de dentro da EC2, pois a Hosted Zone é privada e só resolve dentro da VPC.
